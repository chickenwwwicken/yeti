Remember, Git commits are used to save snapshots of your code at a specific point in time.
Each commit should represent a single logical change to your codebase. For example, a commit might:

- Add a new feature
- Fix a new bug
- Rework a bit of your code to be more readable

I usually make 2 or 3 commits for each hour I spend coding -
that's not a hard rule, but might help you gauge how often you might be committing.

### Assignment
Let's commit your `README.md` change.

1. View your diff. A "diff" is a visual aid that shows you the differences between two files. If you're in VS Code, now that you've saved a change, you should see a blue notification pill on the "source control" icon on the left of your VS Code window.

Click on it, and under "changes" take a look at your `README.md` file - you should see the diff view.

***If you're using the CLI, you can view your diff with the `git diff` command***

2. Stage your change.

```bash
git add .
```
